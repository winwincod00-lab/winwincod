# Disposable PostgreSQL verification — required, NOT RUN

This is a future execution plan, not authorization to connect or migrate now. Use a disposable LOCAL PostgreSQL 15+ cluster, synthetic users/stock/funds only, and no Neon, Supabase, production URL, root .env, carrier or bank transport. Capture server version, SQL checksums, complete results, errors, transaction IDs and role settings. A release engineer must convert these cases into a real integration harness before activation.

## Setup and migration rehearsal

1. Create distinct synthetic migration owner, NOLOGIN integrity owner and restricted application login. Neither app nor integrity owner may be superuser/bypass-RLS; app cannot own/inherit legacy or new tables or CREATE in the selected schema. Create dummy `anon`/`authenticated` roles if replaying the development baseline's REVOKEs. Never reuse real roles/credentials.
2. Reproduce the reviewed PostgreSQL baseline (the local dev initial migration uses `winwincod_dev`) in this disposable instance. Root MySQL history is not executable PostgreSQL. Capture catalog/history, confirm baseline against manifests, and set explicit proposed schema/baseline/role session settings exactly as specified in the SQL files.
3. Execute 000 read-only, then 001–005 with stop-on-error, saving output. Test each phase rollback on injected error, lock timeout and restart after prior committed phases. Confirm no legacy row changed, no opening/cost/settlement fabricated, zero financial/stock events after expansion, and correct FKs/indexes/checks/deferred triggers/ACLs/ownership. Test malformed money/NaN/infinity, integer overflow and numeric(65,30) boundaries; text-money RPC input must reject excessive precision before assignment rounds it.
4. Seed only isolated fixtures with clearly synthetic evidence and signed TEST policies: two sellers, admins, disabled actors, separate grants, products, legacy orders, wallets and attested opening accounts/stock. Do not call these fixture entries real transactions. Activate only after proving every legacy pending/in-flight guard. Check incomplete/contradictory openings and pending requests abort.
5. Use TWO independent connections and explicit barriers, not Promise scheduling alone. Kernels must reject READ COMMITTED. Under SERIALIZABLE, assert winning commit, losing serialization/constraint failure, whole-transaction rollback and retry with original identities. Record SQLSTATE 40001/40P01; do not silently retry new keys. No network call inside an open DB transaction.
